# Oncall Provider

Manages Oncall schedules, layers, triggers, and integrations by a user-generated API token created in Oncall and scoped by the RBAC of the requestor.

## Getting a credential

Log into oncall, go to **Settings -> API Tokens**, click **Create**, and copy the
token. Set it as `ONCALL_TOKEN` (or the provider's
`token` argument)

The token is:

- **scoped** to Oncall and your teams within it
- **time-limited** to 90 days by default, 365 days maximum;
- **tied to your account** and acting as you, revoked automatically if your upstream account is disabled.

## Team Management Limitations

This provider only manages resources within teams that *already* exist.
There is no `oncall_team` resource, only the `oncall_team` /
`oncall_teams` data sources to look one up by name. If you need to create a team in Oncall, do so through the UI.

## Sharing Verb and Resource Scope

Every schedule, trigger, and integration has an `owner_team_id`, set once at
creation from `team_ids`. The owning team controls sharing permissions. If you require `Share` permissions on a resource you don't manage, you must be provided with the `Share` verb in your RBAC

## Secrets are write-only

`oncall_integration`'s outbound auth secret uses Terraform's write-only
attribute pattern (`secret_wo` / `secret_wo_version`).

This requires
**Terraform or OpenTofu >= 1.11**.

## Example Usage

```terraform
terraform {
  # >= 1.11 (oncall_integration's secret_wo).
  required_version = ">= 1.11"

  required_providers {
    oncall = {
      source = "observiply/oncall"
    }
  }
}
provider "oncall" {
  endpoint = "https://oncall.example.com"
  token    = var.oncall_token
}

variable "oncall_token" {
  type      = string
  sensitive = true
}
```

See `examples/complete/` in the provider's repository for more robust examples
