# terraform-provider-oncall

Terraform/OpenTofu provider for [oncall](https://github.com/observiply/oncall).
Built with [terraform-plugin-framework](https://github.com/hashicorp/terraform-plugin-framework).

Status: **scaffold only** — provider configuration (endpoint/token, validation,
auth probe) is wired up; no resources or data sources exist yet
(`tfprovider-07-provider-resources.md` in oncall's `plan/`). Do not publish this
to a registry until that work — and the API gaps tracked in
`tfprovider-05-api-gaps.md` — are done (`tfprovider-00-overview.md §Where I
disagree, item 3`).

## Layout

```
main.go                     provider server entrypoint (providerserver.Serve)
internal/
  client/                   generated from oncall's docs/swagger.json — do not hand-edit
    swagger.json            vendored copy, pinned; CI diffs it against oncall main
    generate.go             //go:generate oapi-codegen directive
    client.gen.go           generated output
  provider/
    provider.go             schema, config (endpoint/token), validation, auth probe
examples/                   used by tfplugindocs to generate docs/
docs/                       generated by tfplugindocs — do not hand-edit once populated
templates/                  tfplugindocs overrides (index.md.tmpl etc.)
```

## Building

```bash
go generate ./...   # regenerate internal/client from swagger.json
go build ./...
go vet ./...
golangci-lint run
```

## Updating the vendored API spec

`internal/client/swagger.json` is a pinned copy of oncall's `docs/swagger.json`,
not a live fetch — a silently-updated spec regenerating the client mid-PR is how
you ship a provider that compiles and lies about the API it talks to. CI's
`spec-drift` job diffs it against oncall `main` on every push/PR. To pick up an
intentional oncall API change:

```bash
cp /path/to/oncall/docs/swagger.json internal/client/swagger.json
go generate ./...
git add internal/client/swagger.json internal/client/client.gen.go
```

## Local development (no registry, no publish step)

Build the provider and point Terraform/OpenTofu at the binary instead of a
registry release, via `dev_overrides`. This repo is developed against
[OpenTofu](https://opentofu.org) (`~/.tofurc`); the same config works for
Terraform under `~/.terraformrc` — the CLI config block is identical, only the
env fallback name differs (`TF_CLI_CONFIG_FILE` works for both).

```bash
go install .

cat >> ~/.tofurc <<'EOF'
provider_installation {
  dev_overrides {
    "observiply/oncall" = "/Users/<you>/go/bin"
  }
  direct {}
}
EOF
```

`go install .` places the binary at `$(go env GOPATH)/bin/terraform-provider-oncall`
— use that directory (`go env GOPATH`, then append `/bin`) as the override path,
not the repo directory. With the override in place, `tofu plan`/`apply` uses your
locally built binary directly; skip `tofu init` for this provider (it will
complain that `observiply/oncall` isn't a real registry provider yet — that's
expected and harmless with dev_overrides active).

## Configuration

```hcl
provider "oncall" {
  endpoint = "https://oncall.example.com" # or ONCALL_ENDPOINT
  token    = var.oncall_token             # or ONCALL_TOKEN (Sensitive)
}
```

- `endpoint` is oncall's base URL. Don't include `/m2m/api/v1` — the provider
  appends it, and tolerates the common mistake of pasting the full path anyway.
- `token` must be an oncall-issued API token (`oncall_pat_...`, minted from the
  oncall UI's Settings -> API tokens). An authentik token or a trigger ingest
  token will be rejected at configure time with a specific error, not a generic
  401 from deep in a resource call.
- Prefer the env vars over a token literal in `.tf` files, which end up in
  version control.
- `Configure` runs an auth probe (`GET /admin/teams`) once, up front, so
  credential problems surface as one clear error instead of N confusing
  per-resource failures. 401 vs 403 vs 503 are distinguished — see
  `internal/provider/provider.go`.

## CI

- `build`: `go generate` (fails the build if the committed `client.gen.go` is
  stale relative to `swagger.json`), `go build`, `go vet`, `golangci-lint`.
- `spec-drift`: diffs the vendored `swagger.json` against oncall `main`.
- `tofu-fmt`: `tofu fmt -check -recursive examples/`.

Runs on standard GitHub-hosted runners — this is a public, standalone repo, not
part of oncall's internal ARC Kubernetes runner set (see oncall's `AGENTS.md`
for why that distinction matters there).
